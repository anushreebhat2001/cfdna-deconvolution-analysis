# Read-level vs site-level deconvolution of ultra-low-pass Nanopore cfDNA

Project question 3: does reading the whole read still help when cfDNA reads are this short, and
does the help depend on how many CpGs each read carries?

Data: Katsman et al. 2026 (bioRxiv 2026.04.15.718632; Zenodo 18100426), 20 colorectal cancer
plasma samples from 5 patients and 22 healthy controls. Tool: CelFiE-ISH from the
`deconvolution_models` package, with the 31-cell-type U250 atlas (16 epithelial types summed as
the tumor score) and, for one exploratory run, the 8-type pan-epithelial "max" atlas.

Every file is fitted twice on identical CpG calls: "whole" keeps the part of each read that lies
inside a marker region intact; "single" (called `cut` in file names) feeds the same calls one per
line. The scripts and result tables call a read part a "string" and a CpG call a "bead".

## What is primary and what is exploratory

- **Primary (the frozen plan, fixed before any result was seen):** `results/scores/`.
- **Exploratory (chosen after seeing the primary results):** `results/checks/`,
  `results/breast/`, `results/breast_max/`, `results/step7/`, `results/factors/`,
  `results/linked/`. They are listed under "Exploratory" in the run order below.

## What is in this repository

Code, sample tables, score tables, check outputs, figures and run logs are stored as plain files.
Not stored, because of size: the read data (`data/`, about 7 GB; the source files are on Zenodo
18100426), the Python environment (`env/`), the intermediate read files and per-fit logs inside
`results/`, and `from_hpc/`.

The estimates of every fit (two small text files per fit) are packed in
`results/fit_outputs.tar.gz`. Unpack them before running a scoring or readout script:

```
tar -xzf results/fit_outputs.tar.gz
```

## Run order

All commands are run from this folder, in bash. Fits use 12 processes; a full-file fit takes
2 to 7 minutes. On a laptop, keep the machine awake during long runs (`caffeinate -i -s`).

Frozen plan (10,766 fits, none failed):

Python scripts are run as `./env/bin/python -I <script>` from this folder. A script whose result
is one text file prints it, so send the output to the file in the Results column, for example
`./env/bin/python -I step_scripts/factors/stage1_checks.py > results/factors/stage1.txt`.
The linked-model scripts are run without `-I`. The `run_*.sh` scripts take the number of
parallel jobs as an optional argument (default 12) and skip fits that are already done.

Commands that take arguments:

```
bash scripts/convert_all.sh [parallel jobs]
bash scripts/marker_all.sh [parallel jobs]
./env/bin/python -I scripts/mix_dilutions.py --meta meta/samples.tsv --totals logs/convert_summary.tsv \
    --marker-dir data/marker_pat --out data/mix [--batch HU012]
./env/bin/python -I step_scripts/step0/step0_compare.py results/step0 \
    data/ref/31CT_U250_Netanel_atlas_over_regions.txt data/ref/31CT_U250_Netanel_merged_regions_file.bed
./env/bin/python -I step_scripts/step1/step1_lookalikes.py --meta meta/samples.tsv --marker-dir data/marker_pat \
    --places data/places/epithelial_u250.bed --label u250 --out results/step1 [--batch HU012]
./env/bin/python -I step_scripts/common/score_pair.py --meta meta/samples.tsv --markers u250 \
    --a "results/step2/{id}/whole" --b "results/step2/{id}/cut" --label A1 --out results/scores
bash step_scripts/common/run_one.sh SRC.pat OUT_PREFIX u250|max [--size N] [--bucket 1|2|3|4+|2+] [--match SEED]
DRY=1 bash step_scripts/factors/run_stage2.sh     # prints the fit commands without running them
```

## Scores

- "How much": mean absolute error between the epithelial estimate and copy-number tumor
  fraction (ichorCNA) times dilution.
- "Yes or no": AUROC of cancer files against healthy controls.
- A gain is positive when the version with longer reads is better. It counts as established
  only if its 95% bootstrap interval (patients and controls redrawn, 2000 rounds) excludes zero.
- Every detection number is reported against all 22 controls, the HU012 controls only and the
  HU083 controls only, because the two healthy groups were sequenced differently.

## Environment

Python 3.11.16 virtual environment in `env/`: numpy 1.26.4, scipy 1.11.4, pandas 2.2.3,
pysam 0.24.1, click 8.5.1, matplotlib 3.11.2, and `deconvolution_models` 0.0.2 installed in
editable mode from `../deconvolution_models`. htslib 1.25 (`bgzip`, `tabix`) on the path.
Keep scipy at 1.11: with scipy 1.17 a CelFiE-ISH fit takes about three times as long, with
identical output. Fits are single-threaded (`OMP_NUM_THREADS=1`) and seeded, so reruns give the
same files.

## Known issues

- **One FAIL in `results/step0/checks.txt`** (sample HU083.68, check C). It comes from a single
  read; see `results/step0/checks_note.txt`. It does not affect the whole-against-single
  comparison.
- **Sequencing run and disease are fully confounded** in this cohort; see
  `writeup/setup_table.md`. The public HU012 control files appear to merge two runs on different
  pore chemistries, and the reads cannot be separated with the files available.
- Fits do not record their iteration count. The CelFiE-ISH likelihood is concave in the
  proportions, and results do not depend on the random start.
- Two bead-matched fits logged "divide by zero in log": a cell type reached exactly zero. The
  outputs are valid.
- `logs/steps_3_to_7.log` and `logs/overnight.log` are from an aborted earlier run; the log of
  the frozen-plan queue is `logs/overnight_frozen_plan.log`.
